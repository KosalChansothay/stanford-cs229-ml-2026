មេរៀនទី ១៣: ការរៀនប្រៀបធៀប និង RAG (Contrastive Learning & RAG)

Stanford CS229 — ម៉ូដែលភាសាធំៗ ការរៀនទម្រង់តំណាង និងការស្វែងរកសេម៉ង់ទិក

ទំព័រដើម / វគ្គសិក្សា / CS229 / មេរៀនទី ១៣

១. សេចក្តីសង្ខេបនៃគំនិតចម្បងៗ

មេរៀននេះបង្ហាញពីការវិវត្តពីម៉ូដែលបង្កើតរូបភាព (Diffusion) ទៅកាន់ពិភពនៃ ម៉ូដែលគ្រឹះ (Foundation Models) និងប្រព័ន្ធភាសាធំៗ (LLMs) ដោយផ្តោតលើបច្ចេកវិទ្យាស្នូលពីរគឺ៖ ការរៀនទម្រង់តំណាង (Representation Learning) និង ការស្វែងរកសេម៉ង់ទិក (Semantic Search)។

មេរៀនពិនិត្យលើដែនកំណត់នៃ Supervised Pre-training និងណែនាំ ការរៀនប្រៀបធៀបដោយខ្លួនឯង (Self-Supervised Contrastive Learning - SimCLR) ដែលប្រើប្រាស់កម្លាំងទាញចូល (Attract) លើគូវិជ្ជមាន និងកម្លាំងរុញច្រាន (Repel) លើគូអវិជ្ជមានដើម្បីទប់ស្កាត់ការដួលរលំ (Collapse)។ នៅផ្នែកចុងក្រោយ មេរៀនបានពន្យល់ពីស្ថាបត្យកម្ម Retrieval-Augmented Generation (RAG) និងគុណសម្បត្តិដ៏លើសលប់របស់វាលើ Fine-Tuning ក្នុងការការពារសុវត្ថិភាពទិន្នន័យ ការកាត់បន្ថយការចំណាយ និងភាពងាយស្រួលក្នុងការធ្វើបច្ចុប្បន្នភាពចំណេះដឹង។

២. គោលគំនិតសំខាន់ៗ & និយមន័យ

  • ការរៀនប្រៀបធៀប (Contrastive Learning): ការបណ្តុះបណ្តាល Embeddings ដោយទាញគូវិជ្ជមានឱ្យជិតគ្នា និងរុញច្រានគូអវិជ្ជមានឱ្យឆ្ងាយពីគ្នា។
  • ការដួលរលំចុះខ្សោយ (Degenerate Collapse): ស្ថានភាពបរាជ័យដែល Encoder ផ្គូផ្គងធាតុចូលទាំងអស់ទៅជាវ៉ិចទ័រថេរតែមួយ ដែលត្រូវបានទប់ស្កាត់ដោយកម្លាំងរុញច្រាននៃគូអវិជ្ជមាន។
  • SimCLR: ក្របខ័ណ្ឌរៀនប្រៀបធៀបដោយខ្លួនឯងលើរូបភាពដែលប្រើប្រាស់ Data Augmentations និងអនុគមន៍បាត់បង់ NT-Xent។
  • RAG (Retrieval-Augmented Generation): ប្រព័ន្ធដែលទាញយកឯកសារពាក់ព័ន្ធពី Vector DB មកភ្ជាប់ក្នុង Prompt ដើម្បីឱ្យ LLM បង្កើតចម្លើយផ្អែកលើការពិតជាក់ស្តែង។
  • ការស្វែងរកកូនកាត់ (Hybrid Search): ការរួមបញ្ចូលគ្នារវាង Semantic Vector Search និង Exact Regex/Keyword Pattern Matching សម្រាប់កូដកម្មវិធី។

៣. រូបមន្តគណិតវិទ្យានៃ SimCLR & តុល្យភាពកម្លាំង

អនុគមន៍បាត់បង់ NT-Xent សម្រាប់គំរូយុថ្កា \(i\)៖

\[\mathcal{L}_i = -\log \frac{\exp(S_{ii} / \tau)}{\exp(S_{ii} / \tau) + \sum_{j \neq i} \exp(S_{ij} / \tau)}\]

តាមរយៈការតាង \(A = \exp(S_{ii}/\tau)\) (គូវិជ្ជមាន) និង \(B = \sum_{j \neq i} \exp(S_{ij}/\tau)\) (គូអវិជ្ជមាន)៖

\[\frac{\partial \mathcal{L}}{\partial A} = \frac{-B}{A(A+B)} < 0 \quad (\text{កម្លាំងទាញចូលឱ្យបង្កើនភាពស្រដៀងគ្នានៃគូវិជ្ជមាន})\] \[\frac{\partial \mathcal{L}}{\partial B} = \frac{1}{A+B} > 0 \quad (\text{កម្លាំងរុញច្រានឱ្យកាត់បន្ថយភាពស្រដៀងគ្នានៃគូអវិជ្ជមាន})\]

រូបភាព៖ អនុគមន៍បាត់បង់ NT-Xent ថយចុះជាម៉ូណូតូនធៀបនឹងភាពស្រដៀងគ្នានៃគូវិជ្ជមាន។

រូបភាព៖ តុល្យភាពកម្លាំង SimCLR ក្នុងលំហបង្កប់។

៤. ស្ថាបត្យកម្ម RAG & ការប្រៀបធៀបជាមួយ Fine-Tuning

រូបភាព៖ ស្ថាបត្យកម្មប្រព័ន្ធ RAG ជាមួយ Vector Database និង Large Language Model។

  • Data Governance: RAG អាចកំណត់សិទ្ធិចូលមើលឯកសារពេល Retrieval បានយ៉ាងងាយស្រួល ឯ Fine-Tuning អាចប្រឈមការលេចធ្លាយទិន្នន័យសម្ងាត់។
  • ការធ្វើបច្ចុប្បន្នភាព: RAG គ្រាន់តែកែប្រែ ឬលុប chunk ក្នុង Vector Database បានភ្លាមៗ ខណៈ Fine-Tuning ទាមទារ re-train ឡើងវិញទាំងស្រុង។
  • ថ្លៃដើមគណនា: RAG មិនទាមទារការបណ្តុះបណ្តាល GPU ថ្លៃៗ និងមិនបាច់ផ្ទុក dedicated model សម្រាប់អតិថិជនម្នាក់ៗឡើយ។
